# Motor decoding contract

The preprocessor selects members by exact annotation strings from the v783 table. A label below is never a fabricated root ID. `cell:<label>` populations are also emitted for audit.

| Runtime output | Real annotation-derived population | Minecraft effect |
|---|---|---|
| `motor_forward` | cell types containing `DNp09`, `DNp12`, `DNp15`, or `DNg13` | forward thrust |
| `motor_turn_left/right` | `DNa01`, `DNa02`, `DNa03`, partitioned by the released `side` annotation | yaw and lateral steering |
| `motor_vertical_up` | `MDN` | vertical lift / moonwalker-like escape component |
| `motor_landing` | `DNp13` | permits the grounded/landing state |
| `motor_escape` and `motor_takeoff` | `DNb01`, `DNb02`, `DNg16`, `DNg42` | rapid evasive acceleration and takeoff |

These are **decoder groupings**, not a claim that a single named descending neuron is the complete biological muscle command. The edge graph and root IDs remain the real v783 data; the grouping-to-Minecraft actuator map is an embodiment approximation. If a particular v783 annotation release has no member for a group, that output is zero and no fake fallback population is created.

Sensory group names (`visual`, `olfactory`, `gustatory`, `mechanosensory`, `thermosensory`) are likewise generated by searching released flow/super-class/cell-class/type/nerve annotations. The generated metadata JSON reports exact membership counts for a build.
